# Extraction-quality benchmarks (EX-02)

`benchmarks/pdf_extraction/` is a reproducible ground-truth benchmark for
PDF extraction: a versioned synthetic corpus of 30 annotated hard pages, a
pluggable provider runner, quality/cost metrics, deterministic RAG probes
and CI non-regression gates.

## Corpus

`fixtures/manifest.jsonl` — one JSON record per page:

- `document_id`, `file`, `family`, `page`, `page_count`
- `license` — every page is `synthetic-generated-cc0`; no proprietary or
  third-party documents are committed
- `source_hash` — `sha256:` of the PDF, verified by `validate`
- `regions[]` — `region_id`, `kind` (text/heading/table/caption/formula/
  figure/decoration), `bbox` in `pdf-points-top-left` coordinates
  (`[x0, y0, x1, y1]`, points, origin top-left), `reading_order`,
  `expected_text`, `excluded` for intentional decorations
- `tables[]` — `rows`, `cols`, `cells[]` with `row/col/rowspan/colspan/text`
- `critical_fields[]` — exact or normalized-numeric business values
- `expect_error` — corrupted/oversized inputs that must fail, never
  "succeed" with fabricated content

Families (30 pages, 18 documents): plain digital, 2- and 3-column, scan,
mixed digital+scan, rotated, ruled and borderless tables, split/merged
tables, multilevel headings, Arabic/RTL, multilingual, invoices, contracts,
charts, formulas, dense financials, handwriting, corrupted and oversized
inputs.

### Annotation rules

- Annotations are emitted by `generate_fixtures.py` alongside the drawing
  commands, then reviewed against the rendered pixels of every page.
- No LLM-generated labels without human verification; ambiguity and
  tolerances are recorded in per-page `notes`.
- Arabic is shaped and bidi-reordered at draw time; `expected_text` is the
  logical-order Unicode string and scoring normalizes with NFKC. Known hard
  case, measured rather than hidden: digit-run ordering inside RTL lines.
- Regeneration needs `requirements-generation.txt` plus system fonts
  (DejaVu Sans — Bitstream Vera license; Noto Sans Arabic — SIL OFL 1.1,
  subset-embedded at draw time). Regenerated bytes change hashes, so rerun
  `validate` and commit the updated manifest together with the PDFs.

## Running

```bash
python -m pip install -e '.[pdf]'
python -m benchmarks.pdf_extraction validate                      # schema + checksums
python -m benchmarks.pdf_extraction run --provider pypdf --out report.json
python -m benchmarks.pdf_extraction run --provider pypdf \
    --baseline benchmarks/pdf_extraction/fixtures/baseline/pypdf.json   # gates
python -m benchmarks.pdf_extraction probes --provider pypdf       # RAG probes
python -m benchmarks.pdf_extraction baseline --provider pypdf --out new-baseline.json
python -m benchmarks.pdf_extraction compare --baseline b.json --candidate c.json
```

Reports are machine-readable JSON: run id, provider id/version/pinned
config, library versions, python/platform/hardware, per-page metrics,
per-family slices, p50/p95 latency, peak memory, cost per 1k pages and
explicit failure ids. **PDF contents never appear in reports or stdout.**

## Metrics

| Metric | Meaning |
| --- | --- |
| `cer` / `wer` | character/word error rate over NFKC-normalized text |
| `region_recall` | fraction of expected text regions recovered (squashed containment) |
| `region_precision` | needs provider blocks; `null` for whole-page text providers |
| `ocr_coverage` | character-weighted recovery of expected ink regions (area-agnostic) |
| `reading_order` | fraction of consecutive region pairs extracted in order |
| `table_structure` | sequence-based **TEDS approximation** over the serialized grid token stream; not full tree-edit TEDS |
| `cell_value_accuracy` | expected cell values recovered (grid position, or text containment when the provider emits no structure) |
| `merged_cell_fidelity` | spanned cells preserved with position and span; needs provider structure |
| `field_accuracy` | critical-field exact/normalized-numeric hits |
| `silent_omission` | page reported content success while missing expected regions |

`null` means "no ground truth / not applicable for this provider" and is
excluded from aggregates. pypdf emits no layout blocks or table structure,
so its baseline cannot gate `region_precision`, `table_structure` or
`merged_cell_fidelity`; structural gates activate for structure-aware
providers (see `tests/test_extraction_benchmark_gates.py`).

## Gates and CI

`.github/workflows/extraction-benchmarks.yml` runs on Python 3.11 and 3.12:
manifest validation, a benchmark run gated against
`fixtures/baseline/pypdf.json`, the RAG probes, and the benchmark test
suite. Gate thresholds are the **measured values of the checked-in baseline
run** with zero tolerance on deterministic metrics — never invented
numbers. Timings, memory and cost are reported but never gated.

The gates are proven to bite by tests: a synthetic silent region omission,
an intentionally degraded (merged-cells-split) table extraction, and an
unsafe success on corrupted input are all rejected.

## RAG probes

`fixtures/probes.json` labels queries with expected
`(document_id, page, region_id)` citations on hard tables/figures/RTL pages.
Each region the provider verifiably recovered becomes one chunk in a
deterministic hashing-embedding index (no network, no model drift);
Recall@5, MRR and citation resolution are reported. `citation_resolution`
caps Recall@K and keeps extraction failures visible: a dropped region
removes its citation from the index.

## Deliberate scope limits

- Heavyweight GPU/cloud benchmarks (Docling, OCR, VLM providers) are
  opt-in follow-ups (EX-04/EX-06), not part of CI core.
- No universal "quality score": metrics stay separate and comparable
  across providers.
- Verification integration uses the `silent_omission` proxy until EX-01's
  page-status model lands.
